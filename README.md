# Fantom — сайт квест-рума (Усть-Каменогорск)

Тёмный кинематографичный одностраничник с онлайн-записью и мгновенными
уведомлениями в Telegram.

**Стек:** Next.js 16 (App Router) · React 19 · TypeScript · Tailwind CSS v4

---

## Быстрый старт

```bash
npm install
npm run dev     # http://localhost:3000
npm run build   # production-сборка
npm run start   # запуск production-сборки
```

## 2. Изображения: сгенерированные сцены, не фото из 2ГИС

На сайте — **сгенерированные арт-дирекшн-сцены**, по одной на комнату
плюс фон первого экрана. Это не фотографии зала: это подборка под тему
каждой комнаты, чтобы сайт показывал атмосферу и не выглядел макетом.
Перед публикацией её заменяют съёмкой клуба.

| Файл | Где используется |
|---|---|
| `hero-corridor.jpg` | фон первого экрана |
| `room-sanatorium.jpg` … `room-foyer.jpg` | обложки шести комнат |

Всё это 0.79 МБ на семь файлов — против 26.7 МБ, которые занимала
подборка из 2ГИС и Instagram.

### Почему убрали скачанные фото

В открытой карточке 2ГИС 45 снимков, и почти все — это роспись на стене,
актёры у входа и **таблички с ценами**. Как обложки комнат они не работают:
гость по ним не понимает, что его ждёт внутри, а снимок прайса нельзя
ставить лицом к посетителю. Видео 2ГИС отдаёт только потоком HLS — значит,
на сайте висел бы внешний CDN с чужой доступностью.

Сгенерированная серия решает это: одна световая схема, один ракурс,
ни одного постороннего элемента.

### Как заменить на реальную съёмку

1. Сфотографируйте каждую комнату с одной точки и с одним светом —
   ровная серия важнее отдельных удачных кадров.
2. Положите файлы в `public/media/` под теми же именами.
3. Обновите подписи в `src/data/scenes.ts`: `alt` должен описывать то,
   что реально видно на кадре.

Размер: длинная сторона 1400px для обложек, 2000px для фона,
JPEG q82 — этого хватает на ретине при 400px в карточке.

### OG-изображение

`public/og.jpg` — 1200×630, собран из фона первого экрана с затемняющим
градиентом (`sharp`, `fit: cover`). Превью при пересылке ссылки в мессенджерах.

## 2.1 Шрифты

Три декоративные гарнитуры плюс основной текст. **Все с подмножеством
`cyrillic`** — и это не деталь, а исправление: прежний Creepster
кириллицу не содержит, поэтому все русские заголовки (их два десятка)
молча отрисовывались системным запасным шрифтом, и «хоррор» оставался
только на латинском логотипе.

| Токен | Гарнитура | Где применяется |
|---|---|---|
| `font-display` | Rubik Wet Paint | заголовки, названия комнат, цифры, логотип |
| `font-accent` | Ruslan Display | старославянская вязь — названия комнат |
| `font-glitch` | Rubik Glitch | «сбойные» подписи: короткие строки, где и так есть CSS-глитч |
| `font-sans` | Inter | основной текст, интерфейс, подписи полей |

Гарнитуры подбирались **по образцам, а не по названию**: страница
с кандидатами отрисовывалась в headless Chrome и сравнивалась глазами —
по кириллице, читаемости на мелком кегле и характеру.

Размер заголовка первого экрана подобран под новую гарнитуру:
Rubik Wet Paint заметно шире Creepster, и при прежних `21vw` слово
«FANTOM» ломалось на две строки. Сейчас `15.5vw` — шесть знаков
занимают около 90% ширины на 320–414px.


## 3. Настройка Telegram-бота

Форма → `POST /api/booking` → `sendMessage` вам в чат.

### Шаг 1. Создайте бота

1. Откройте [@BotFather](https://t.me/BotFather) в Telegram.
2. `/newbot` → задайте имя и username (например, `fantom_uka_bot`).
3. Скопируйте **токен**.

### Шаг 2. Узнайте `chat_id`

Добавьте бота в группу (или напишите ему в личку), затем откройте:

```
https://api.telegram.org/bot<ТОКЕН>/getUpdates
```

Найдите `"chat":{"id": -1001234567890}` (группа) или положительный id (личное сообщение).

### Шаг 3. Задайте переменные окружения

Создайте `.env.local` в корне проекта:

```env
TELEGRAM_BOT_TOKEN=1234567890:AAHxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
TELEGRAM_CHAT_ID=-1001234567890
```

### Шаг 4. Проверьте

```bash
npm run dev
```

Отправьте тестовую заявку через форму — она придёт в Telegram за секунду.

> **Без настроенного бота форма всё равно работает** (ответ 200, заявка пишется
> в лог сервера) — чтобы демо можно было показывать клиенту до подключения.

> **При деплое на Vercel** задайте те же переменные в
> Dashboard → Project → Settings → Environment Variables, затем передеплойте.

## 5. Дизайн-система

Все токены — в `src/app/globals.css` внутри блока `@theme`:

| Токен | Значение | Назначение |
|---|---|---|
| `--color-void` | `#0a0a0a` | основной фон |
| `--color-ash` | `#0d0d0d` | фон чередующихся секций |
| `--color-smoke` | `#141414` | карточки, панели |
| `--color-blood-700` | `#8a0303` | основной красный акцент |
| `--color-blood-500` | `#b8121a` | hover, подсветка |
| `--font-display` | Creepster | тревожные заголовки |
| `--font-sans` | Inter | основной текст |

**Правила темы:**
- фон никогда не чисто-чёрный — только `#0a0a0a`/`#0d0d0d`;
- красный — точечно (кнопки, hover, индикаторы), **не заливками**;
- текст не чисто белый, а `#c9c9c9` — белый на чёрном в хорроре выглядит дёшево;
- display-шрифт — только для заголовков, для текста — Inter.

Сменить акцентный цвет (например, на ржавый) достаточно в одном месте:
поменяйте `--color-blood-*`.

## 6. Карта: почему своя, а не 2ГИС в iframe

**2ГИС запрещает встраивание.** Их страницы отдают заголовок
`Content-Security-Policy: frame-ancestors 'none'` — в iframe будет пустота.
Официальный виджет требует платный ключ API. Яндекс.Карты тоже убраны:
для цокольного этажа поиск по строке адреса попадал во вход в ТЦ, а не
в нужную точку.

Поэтому карта своя: **Leaflet + тайлы OpenStreetMap**, метка — по точным
координатам входа из ссылки 2ГИС (82.595183, 49.968637), zoom 17.
Тайлы приглушены фильтрами, метка — пульсирующее кровавое кольцо.

**2ГИС при этом не потерян** — он остаётся источником данных и целью для
кнопок «Открыть в 2ГИС» (карта, блок контактов). Это ровно то, что нужно
гостю: быстрый маршрут в его любимом приложении.

Файлы: `src/components/DarkMap.tsx`, координаты — `BUSINESS.geo` в
`src/data/quests.ts`.

> Leaflet грузится **динамическим импортом** — он обращается к `window`
> уже на этапе импорта модуля, и статический импорт роняет пререндер
> Next.js с «window is not defined». Динамика заодно выносит ~51 КБ
> в отдельный чанк, который не грузится вместе с основным бандлом.

## 7. WebGL-дым (ShaderBackground)

`src/components/ui/gem-smoke-diamond.tsx` — один WebGL-канвас без
зависимостей. Оригинал: Paper Shaders «Gem Smoke» (Apache-2.0).

**Палитра перекрашена под проект** (в оригинале был самоцветный градиент):
уголь `#0a0a0a` → кровавый `#8a0303` → ржавый `#6b4a24` → светлая кровь.
Плюс приглушена насыщенность (0.82) и усилена виньетка (0.55) — иначе
дым выглядел бы «пластиково» и не вписывался в хоррор-тему.

Почему подходит под требование «мрак»:
- время замедлено (`timeScale 0.55`) — дым клубится, а не мельтешит;
- `prefers-reduced-motion` → рисуется **один статичный кадр**;
- вне экрана рендер полностью останавливается (IntersectionObserver);
- при `visibilitychange` на скрытой вкладке рендер тоже стопорится;
- DPR ≤ 2 и потолок ~2 млн пикселей — не греет GPU на 4K;
- если WebGL недоступен — тихий откат на CSS-фон родителя.

Хотите темнее — крутите `UNIFORMS.vignette` (0.55) и `brightness` (-0.02).
Хотите быстрее — поднимайте `timeScale`.

## 8. Компоненты React Bits

Взяты с [reactbits.dev](https://reactbits.dev) (лицензия **Apache-2.0**,
репозиторий `DavidHDev/react-bits`). Лежат в `src/components/reactbits/`,
переписаны на TypeScript и подогнаны под палитру Fantom.

| Компонент | Где используется | Зачем именно он |
|---|---|---|
| `DecryptedText` | слоган в Hero | Текст «декодируется» из шума — будто вскрывают повреждённый файл изнутри квеста. Самое тематичное попадание |
| `GlitchText` | подпись Hero, название в модалке, «Пути назад нет» | Сигнал «сбоит». У оригинала тени красный/циан — заменены на кровь и холодный ржавый, иначе неон выбивается из темы |
| `SpotlightCard` | карточки квестов | За курсором идёт кровавое пятно — карточка «освещается фонариком в тёмном коридоре». Пятно рисуется псевдоэлементом, лишних DOM-узлов нет |
| `ClickSpark` | CTA в Hero, кнопка «Забронировать» | Искры из точки клика — тактильный отклик «вы тронули дверь» |
| `CountUp` | статистика под квестами | Реальные цифры из 2ГИС «накручиваются» при появлении |
| `GradualBlur` | низ Hero, границы секций | Контент уходит в темноту, а не обрезается прямой линией |

### Что изменено против оригинала

- **Типы.** Всё переведено на TypeScript.
- **`motion/react` → `framer-motion`.** `CountUp` в оригинале тянет новый
  пакет `motion`; в проекте уже стоит `framer-motion`, дублировать
  зависимость не стали.
- **reduced-motion через хук.** `usePrefersReducedMotion` построен на
  `useSyncExternalStore`, а не на `useState` + `useEffect` — так не
  возникает каскадный ререндер (на это ругается правило
  `react-hooks/set-state-in-effect`) и корректно работает SSR.
- **ClickSpark не крутит rAF впустую.** В оригинале цикл отрисовки
  работает бесконечно, даже когда искр нет. Здесь он стартует по клику и
  останавливается, когда искры догорели.
- **GradualBlur без `filter: blur`.** Вместо вложенных слоёв с blur
  используются ступенчатые полупрозрачные градиенты — дешевле для GPU.
- **Стили вшиты.** GlitchText и SpotlightCard используют классы
  `rb-glitch*` / `rb-spotlight` в `globals.css`, чтобы не тащить
  глобальные `.glitch` и `.card-spotlight` в проект.
- **Без WebGL-зависимостей.** Взяты только лёгкие компоненты; тяжёлые
  (three.js, ogl) не подключались — на фоне уже работает собственный
  WebGL-шейдер из `ui/gem-smoke-diamond.tsx`.

## 9. Хоррор-слой: звук, взгляд, готика

### Звук — синтез через Web Audio, без файлов

`src/lib/horrorAudio.ts` + `src/components/horror/SoundToggle.tsx`.
Аудиофайлов на проекте **ноль** — всё генерируется в браузере:

| Звук | Как сделан | Когда играет |
|---|---|---|
| `drone` | две расстроенные пилы 48 Гц + lowpass, медленный LFO | фоном, пока звук включён |
| `heartbeat` | синус 78→34 Гц, сдвоенный удар (lub-dub) | по таймеру, темп зависит от интенсивности |
| `door` | шумовой всплеск 380 Гц + синус 120→28 Гц | клик по «Войти», успешная запись |
| `sting` | highpass-шум + пила 1600→90 Гц | закрытие модалки квеста |
| `whisper` | шум в полосе 1400 Гц с АМ-модуляцией | заготовка, сейчас не вызывается |
| `click` | короткий квадратный щелчок | интерфейсные акценты |

Почему синтез, а не записи: ноль трафика, ноль лицензионных рисков,
параметры связаны со страницей (пульс ускоряется), и ничего не грузится
до клика гостя.

**Правила включения звука:**
- **выключен по умолчанию** — `AudioContext` не создаётся вообще, пока
  гость не нажмёт тумблер (политика автовоспроизведения всех браузеров);
- громкость жёстко ограничена: `MASTER = 0.18`;
- клавиша `M` — переключение;
- на скрытой вкладке звук глушится за 0.2 с;
- тумблер стоит в шапке и в подвале.

Любая часть страницы может проиграть звук, не зная про Web Audio:

```ts
import { sfx } from "@/components/horror/SoundToggle";
sfx("door");
```

### Взгляд из темноты

`horror/GazeEye.tsx` — глаза по краям Hero, которые **следят за курсором**
и моргают в случайные моменты. Радужка тёмно-бордовая (кровь в темноте),
белок мутный, а не белый.

Позиция зрачка пишется прямо в CSS-переменные `--eye-x/--eye-y` мимо
React-состояния: иначе на каждый кадр `mousemove` шёл бы ререндер дерева.
На тач-устройствах глаза просто смотрят в никуда; при `prefers-reduced-motion`
зрачки стоят по центру, моргание выключено.

`horror/Gothic.tsx` — стрельчатая арка с нервюрой, клиновидная розетка-разделитель,

### Табло наблюдения

Используется как намёк на слежку: `ОБЪЕКТ В СЕТИ` в Hero, `СИГНАЛ: 06:00`

## 10. Мрачные эффекты и анимации

- Все анимации — только `transform` / `opacity` (без layout-свойств).
- Появление секций — через `Reveal` («раскрытие из темноты»).
- Скример-толчок в секции квестов — **один раз**, отключается при
  `prefers-reduced-motion`.
- Кровавый след за курсором — только на устройствах с мышью.
- При `prefers-reduced-motion: reduce` глобально отключаются flicker, drift и
  тряска — остаются мягкие fade.

## 11. Адаптивность и замеры

Mobile-first: сначала 320–414px, потом всё, что выше.

| Ширина | Особенности |
|---|---|
| 320–414px | свайп-карусели комнат и отзывов, меню-бургер, липкая кнопка записи, тач-таргеты ≥44px |
| 768px | шапка остаётся мобильной: четыре пункта навигации плюс логотип и кнопка в строку не влезают, поэтому навигация в шапке появляется только с 1024px |
| 1024px+ | навигация в шапке, сетка комнат в 3 колонки, hover-эффекты, след за курсором |

### Длина страницы

Один и тот же контент можно разложить так, что до кнопки записи будет
четыре экрана прокрутки или двадцать. На телефоне было **13 483px** —
почти восемнадцать экранов, из них три с половиной занимали галерея,
видеостена и лента Instagram, не добавлявшие ничего нового к уже
прочитанному. Сейчас **8 143px**: те же комнаты, правила, отзывы и форма,
но без блоков «просто чтобы было».

### Куда ведёт путь гостя

1. **Первый экран** — что это и сколько стоит, сразу кнопка.
2. **Комнаты** — свайп-карусель; карточка отвечает на «страшно ли»,
   «сколько нас», «сколько денег».
3. **Как проходит** и **отзывы** — снятие возражений.
4. **Форма** — с видимым итогом по сумме.
5. **Контакты и карта**.

Плюс липкая кнопка записи внизу экрана — в зоне большого пальца.
Она появляется после первого экрана и уходит, когда форма уже в кадре,
чтобы не закрывать её собой.

### Запись на телефоне

Отдельно проверялась и дорабатывалась именно мобильная запись —
`npm run audit:booking` проходит её настоящими касаниями.

| Что было | Что стало |

| Липкая панель записи пропадала после формы: пролистав к контактам и подвалу, гость терял кнопку до конца страницы | Панель прячется, **только пока форма реально в кадре**. Проверка была односторонней (сравнивался лишь верх секции) — добавлено условие по низу |

### Контраст

Токены серого подобраны по расчёту, а не на глаз:

| Токен | Значение | На `smoke #141414` |
|---|---|---|
| `ash-text` | `#c9c9c9` | 11.4:1 |
| `dim-text` | `#a3a3a3` | 7.3:1 |
| `faint-text` | `#808080` | 4.7:1 |

Прежние `#5e5e5e` и `#8a8a8a` давали 2.84:1 — то есть мелкие подписи
на карточках («Сложность», «Время», «16+», «₸ / чел.») были нечитаемы.
Акцент для текста — `blood-300 #e04a4e` (4.6:1); `blood-500` остался
для заливок и декора, как текст он давал 1.9:1.

### CLS

| Было | Стало |
|---|---|
| 0.13–0.18 | **0.00–0.04** |

Причина сдвигов была не в картинках, а в анимации «расшифровки» слогана в Hero:
пока `DecryptedText` подменял буквы, менялась ширина строк и текст на секунду
занимал на строку больше — кнопки под ним прыгали. Лечится резервом высоты
(`min-height` под самую длинную фазу) и компенсацией отступа кнопок.

### LCP

Замер показал 4.1–4.5 с на 375px. Разбор кандидатов (`audit-metrics` печатает
их последовательность) дал ответ: самым крупным элементом страницы были
**буквы заголовка**, а они появлялись только после гидратации React —
`titleIn` зажигался таймером через 700 мс после монтирования, плюс задержка
проявления каждой буквы. То есть LCP зависел от загрузки JS.

| Было | Стало |
|---|---|
| 4.1–4.5 с (375px) | **0.25–1.9 с** |

Что сделано: появление букв переведено с перехода по состоянию React на
CSS-кадры (`@keyframes letter-in`). CSS-анимация стартует от первой отрисовки
разметки и от JS не зависит. Заодно в блоке `prefers-reduced-motion`
обнулены `animation-delay` и `transition-delay` — с ними контент
с `fill-mode: both` оставался невидимым до конца задержки.

Остаток LCP (~1.9 с на 414px) — это абзац-слоган, который проявляется
по таймеру через `titleIn`. Это уже внутри «хорошей» зоны (< 2.5 с),
поэтому дальше не трогали.

### Известные послабления

- Подписи полей формы — 33px по высоте. Это меньше 44px из внутреннего
  правила проекта, но выше минимума WCAG 2.5.8 (24px): подпись стоит
  вплотную к своему полю и не конкурирует с ним.
- `aria-controls="mobile-menu"` ссылается на панель, которой нет в DOM,
  пока меню закрыто. Ссылка разрешается в момент открытия — так делают
  почти все реализации, и это не ломает screen reader.
- Сдвиги вёрстки в Hero остались на уровне ~0.01: анимация «расшифровки»
  всё ещё может занять лишнюю строку, но резерв высоты не даёт этому
  сдвинуть кнопки за пределы допуска.
- Кнопка отправки формы активна всегда, проверка идёт по нажатию
  (см. раздел «Форма» в п. 12). Это сознательный отказ от `disabled`:
  отключённая кнопка не объясняет, чего не хватает.

### Движение: что и зачем

Принцип — движение должно что-то сообщать, а не просто быть. Поэтому
у каждой анимации есть причина, и все они отключаются
`prefers-reduced-motion` (глобальное правило гасит длительность).

| Где | Что происходит | Зачем |
|---|---|---|
| Бургер в шапке | три линии сходятся и наклоняются в крест | видно, что состояние переключилось, без подмены иконки |
| Полоса под шапкой | волосяная линия прогресса чтения | страница ~8 100px, надо понимать, сколько осталось до записи |
| Кнопки записи | сжимаются на 3% при нажатии | отклик «нажатие принято» — на телефоне нет hover |
| Карточки комнат | стрелка уезжает вправо при наведении | показывает, куда ведёт нажатие |
| Карточка «хита» | рамка дышит по контуру | выделяет рекомендуемую комнату, не добавляя плашку |
| Обложка комнаты | блик-заглушка до загрузки | под тяжёлым кадром не пустое чёрное пятно |
| Липкая панель записи | выезжает после первого экрана | кнопка в зоне большого пальца, а не в шапке |
| Поля формы | подсветка + рамка при фокусе | видно, где стоит курсор (WCAG 2.4.7) |

Полоса прогресса пишется через `transform: scaleX`, а не `width`:
масштаб считает композитор и не вызывает пересчёт вёрстки на каждый кадр.
Событие `scroll` прорежено одним `requestAnimationFrame`.

### Форма: почему кнопка всегда активна

Кнопка «Забронировать место» не блокируется до заполнения формы. Отключённая
кнопка — тупик: человек не понимает, чего от него хотят, и не может получить
объяснение. Вместо этого нажатие всегда срабатывает, форма называет первое
проблемное поле и **переводит туда фокус** — на телефоне иначе пришлось бы
искать ошибку глазами по всей странице.

Итог по сумме появляется сразу после выбора комнаты: гость должен понимать,
на какую сумму соглашается, ещё до звонка администратора.

> **Про цены.** На одном из фото 2ГИС видна табличка «Пакет хоррор» с ценой
> 5500 ₸ за человека. Она относится к пакету целиком, а не к конкретной
> комнате, поэтому цены в `QUESTS` остались плейсхолдерами — угадывать
> по фотографии нельзя. Итог в форме считается как `игроки × цена`,
> то есть предполагает цену за человека (так же подписана карточка).
