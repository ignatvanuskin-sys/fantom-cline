## 2. ЦЕЛЬ ПРОЕКТА

Сайт должен решать одну задачу лучше всего остального на рынке квестов города: **превратить посетителя в напуганного, но заинтригованного человека, который тут же бронирует игру**. Это не информационная визитка — это часть самого хоррор-опыта, первое «прикосновение страха» ещё до того, как команда переступила порог квеста.

Вторичная цель (для владельца бизнеса): удобная, не требующая звонков онлайн-запись, снижающая нагрузку на администратора.

## 3. ЦЕЛЕВАЯ АУДИТОРИЯ

- Молодёжь и взрослые 16–35 лет, ищущие развлечение для компании друзей, дня рождения, корпоратива, первого свидания «на слабо».
- Заходят преимущественно **с телефона** — вечером, в пятницу/субботу, часто уже определившись «куда идём сегодня» и им нужно быстро увидеть комнаты и записаться, не открывая Instagram и не звоня.

## 4. ДИЗАЙН-КОНЦЕПЦИЯ

### 4.1 Общее настроение
Тёмный, кинематографичный хоррор-дизайн — сайт должен ощущаться как заброшенное, зловещее пространство, а не как обычный лендинг с тёмной темой. Референсы по духу (не копировать 1:1, брать атмосферу и подход к сторителлингу через скролл): сайты уровня *awwwards* для horror-брендов, промо-страницы фильмов ужасов, сайт https://epedvcuwnxviilxbupwjcroyal.com/ (по ощущению кинематографичности и work with darkness/light).

### 4.2 Палитра
- Основной фон: почти чёрный (`#0a0a0a`–`#0d0d0d`), не чистый `#000`, чтобы избежать «дешёвого» вида.
- Акцентный цвет: кроваво-красный (`#8a0303`–`#b8121a`) — используется точечно (кнопки, hover, кровавые потёки, заголовки при появлении), не заливками.
- Вторичный акцент: тускло-зелёный/болотный или ржавый металлик для «индустриального ужаса» (по желанию, если тематика квестов это поддерживает).
- Текст: не чисто белый, а слегка сероватый (`#c9c9c9`–`#e0e0e0`) — белый на чёрном при хорроре читается «слишком чисто».

### 4.3 Типографика
- Заголовки: тревожный, слегка «рваный» или готический шрифт (display-шрифт с характером — напр. в духе `Creepster`, `Nosifer`, `Butcherman` для акцентных заголовков — использовать точечно, не для всего текста, иначе будет нечитаемо).
- Основной текст: чистый, хорошо читаемый sans-serif (напр. `Inter`, `Manrope`) — контраст «пугающий заголовок / спокойный читаемый текст» усиливает эффект.
- На мобильном — обязательно проверить читаемость акцентного шрифта в мелком размере, при необходимости заголовки на мобильном упрощать до более читаемого варианта того же настроения.

### 4.4 Атмосферные приёмы (визуал без анимации)
- Текстуры: лёгкий шум/гранж-оверлей (film grain) поверх всего сайта — придаёт «плёночный», тревожный вид.
- Виньетирование краёв экрана (затемнение по углам).
- Царапины, потёртости, случайные трещины как декоративные SVG-элементы между секциями вместо ровных прямых разделителей.
- Фотографии комнат/актёров — с тёмной цветокоррекцией, лёгким size/contrast boost, возможно duotone (чёрный + красный) на превью карточках, полноцветные — в лайтбоксе/детальной странице.

## 5. АНИМАЦИИ — КОНКРЕТНЫЕ МЕХАНИКИ

Анимации — ключевое требование клиента, они должны **транслировать страх**, а не быть декоративными «плюшками». Конкретные механики по секциям:

1. **Первый экран (Hero)**:
   - Затемнённый/размытый фон-видео или статичное изображение коридора/комнаты квеста, которое на загрузке проявляется через flicker-эффект (имитация мигающей лампы) — 2–3 резких затемнения перед стабилизацией.
   - Заголовок появляется буквами/словами с эффектом дрожания (glitch/shake), будто текст «испуган» — можно на CSS keyframes или через Framer Motion / GSAP.
   - Курсор (только desktop) может оставлять лёгкий кровавый/туманный след при движении по hero-секции — красиво, но не мешать читаемости.

2. **Скролл-сторителлинг**:
   - При скролле вниз секции проявляются не просто fade-in, а через «раскрытие из темноты» — например, элемент выезжает из-под виньетки/тени, как будто выходит на свет фонарика.
   - Параллакс-слои: задний фон (туман/пыль) движется медленнее переднего плана — создаёт глубину пространства.
   - Скример-эффект **дозированно и по вкусу**, не навязчиво: один-два коротких (0.15–0.2 сек) резких визуальных «толчка» на ключевых точках сайта (например, при первом появлении карточек квестов) — лёгкая тряска экрана или доля секунды мелькающего силуэта на фоне. Обязательно с возможностью выключить/уменьшить через `prefers-reduced-motion`.

3. **Карточки квестов (грид)**:
   - При hover (desktop) / при появлении во вьюпорте (mobile) карточка «оживает»: обложка чуть темнеет/дрожит, появляется CTA-кнопка «Забронировать» с эффектом проявления из тумана.
   - Индикатор сложности квеста — визуализировать не просто текстом/звёздами, а «шкалой пульса» (растущий и вибрирующий индикатор), усиливающий ощущение риска.

4. **Форма записи**:
   - При выборе времени/даты — лёгкая «подсветка» доступных слотов, будто фонариком по расписанию.
   - После успешной отправки заявки — короткая, эффектная (но не раздражающая) анимация подтверждения в духе «дверь заперлась» / «билет закомпостирован» с текстом-предупреждением вроде «Пути назад нет».

5. **Общее правило**: все анимации должны быть на CSS transforms/opacity (не layout-свойства) для производительности, с `will-change` там где нужно, и обязательной поддержкой `prefers-reduced-motion: reduce` (для этих пользователей — плавные fade без тряски/flicker).

## 6. ТЕХНОЛОГИЧЕСКИЙ СТЕК

- **Frontend**: React (Next.js рекомендуется для SEO/производительности при статичном контенте) + TypeScript.
- **Стили**: Tailwind CSS для скорости разработки + кастомные CSS-переменные для темы (цвета, тени, grain-текстура).
- **Анимации**: Framer Motion — для скролл-reveal, hover-состояний, переходов между секциями; GSAP + ScrollTrigger — если нужны более сложные параллакс/сторителлинг сцены на скролле.
- **Хостинг**: Vercel (быстрый деплой, хорошо работает с Next.js) либо Railway — в зависимости от того, нужен ли бэкенд для записи.
- **Форма записи → уведомление**: отправка заявки на бэкенд-эндпоинт (Next.js API route / отдельный FastAPI-сервис), который пересылает данные в Telegram-бота владельцу (Bot API `sendMessage`) — этот паттерн уже проверен на других проектах клиента и должен быть переиспользован: простая, надёжная связка «форма на сайте → мгновенное уведомление в Telegram» без необходимости отдельной админки.
- **Хранение заявок** (опционально, если нужна история): Google Sheets через API или простая БД (SQLite/Postgres) — если объём небольшой, Google Sheets проще для владельца.

## 7. СТРУКТУРА САЙТА (SPA с якорными секциями, одностраничник — оптимально для конверсии)

1. **Hero** — атмосферное вступление, название «Fantom», короткий тревожный слоган, CTA «Выбрать квест» / «Забронировать».
2. **О квестах** — грид карточек всех комнат: обложка, название, сложность, длительность, кол-во игроков, возрастное ограничение, цена, кнопка «Подробнее» / «Забронировать».
3. **Детали квеста** (модальное окно или отдельная страница на каждый квест) — фотогалерея, легенда/сюжет, технические детали, отзывы именно по этому квесту, кнопка записи с предзаполненным выбором.
4. **Как проходит игра** — короткий пошаговый блок (правила, что взять с собой, ограничения по здоровью/возрасту) — важно для хоррор-квестов, снимает тревогу перед оплатой.
5. **Отзывы** — карусель/грид отзывов (из Instagram/2GIS, если есть реальные — использовать; иначе плейсхолдеры с пометкой TODO).
6. **Онлайн-запись** — центральный функциональный блок (см. п.8).
7. **Контакты и карта** — адрес (ул. Назарбаева, 50), встроенная карта (2GIS/Google Maps), часы работы, телефон, ссылка на Instagram.
8. **Футер** — навигация, соцсети, копирайт.

## 8. ФУНКЦИОНАЛЬНОСТЬ ОНЛАЙН-ЗАПИСИ

- Выбор квеста (если пользователь пришёл не с конкретной карточки — dropdown/список).
- Выбор даты (календарь, ближайшие 14 дней) и доступного времени (слоты, напр. с шагом 30–60 мин, в реальной версии — синхронизировать с реальным расписанием клиента; на этапе разработки — статично заданные слоты с TODO-комментарием на интеграцию).
- Количество игроков (с учётом мин/макс для каждого квеста).
- Контактные данные: имя, телефон (с маской ввода под казахстанский номер +7).
- Кнопка отправки с загрузочным состоянием и понятным подтверждением после отправки.
- Уведомление администратору в Telegram сразу после заявки (см. стек, п.6) — включить в уведомление: квест, дату/время, кол-во игроков, имя и телефон клиента.
- Форма должна валидироваться на клиенте (обязательные поля, формат телефона) до отправки.

## 9. МОБИЛЬНАЯ ВЕРСИЯ — ПРИОРИТЕТ

Это ключевое требование клиента: **разрабатывать mobile-first**, а не адаптировать десктоп под телефон.

- Все макеты сначала проектируются под ширину ~375–414px, затем масштабируются вверх для планшета/десктопа.
- Тяжёлые анимации (параллакс с несколькими слоями, курсорные эффекты) — упрощать или отключать на мобильных для производительности; оставлять только лёгкие transform/opacity-анимации, которые не «тормозят» скролл.
- Карточки квестов — вертикальный скролл-стек или горизонтальный свайп-карусель (свайп даёт более «нативное» ощущение на телефоне, чем сетка 2×2, которая на маленьком экране превращается в мелкие превью).
- Форма записи — крупные тач-таргеты (мин. 44×44px), нативные `<input type="date">`/кастомный time-picker, оптимизированный под палец, а не под курсор мыши.
- Плавающая липкая кнопка (sticky CTA) «Забронировать» внизу экрана на мобильном — всегда доступна, не требует скролла до формы.
- Изображения — responsive (`srcset`/Next.js `<Image>`), сжатые под мобильный трафик, ленивая загрузка (lazy loading) всего, что не в первом экране.
- Проверка производительности: Lighthouse mobile score — ориентир 85+ по Performance даже с учётом анимаций (использовать `next/image`, code-splitting, отложенную загрузку тяжёлых библиотек анимации там, где возможно).

## 10. ТОН И ПРИМЕРЫ ТЕКСТОВ

Тексты должны быть короткими, тревожными, «шепчущими», а не рекламно-восторженными. Примеры направления (адаптировать под реальные квесты клиента):

- Hero-слоган: *«Дверь закроется. Свет погаснет. Обратного пути не будет — 60 минут, чтобы выбраться»*.
- CTA-кнопки: не «Забронировать», а *«Войти, если осмелишься»* / *«Забронировать место»* — баланс атмосферы и функциональности (в самой форме — уже чёткий, понятный call to action без излишней театральности, чтобы не мешать конверсии).
- Описания квестов — 2–3 коротких предложения атмосферного сюжета, без спойлеров решений.

## 11. ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ

- SEO: корректные `<title>`/`meta description` для каждой секции/квеста, семантическая HTML-разметка, Open Graph-теги (важно — превью в соцсетях/при пересылке ссылки в мессенджерах должно цеплять атмосферой).
- Доступность: `alt`-тексты на всех изображениях, контраст текста читаемый даже с учётом тёмной темы (WCAG AA минимум для основного текста), поддержка `prefers-reduced-motion` (см. п.5).
- Кроссбраузерность: Chrome, Safari (включая iOS Safari — часто «слабое звено» для сложных CSS-анимаций), Firefox.
- Скорость загрузки: оптимизация шрифтов (`font-display: swap`), lazy-load видео в hero, если используется видеофон — обязательно с постером/fallback-изображением для медленного интернета.
